# 0.23.0 fresh-start loader readiness fix

Isolated build and packaged verification passed on 2026-10-16 at 09:33 Eastern. Live acceptance is pending. This is isolated QA, not a Main replacement or a Data/Library migration.

The 0.22 manual attempt confirmed that the publication fix now allows Steam dispatch and exact game binding. The game loaded the same SHA-256 loader DLL used by Main and produced its outfit-worker ARMED log, but not the separate loader-ready report. Read-only process/module/thread inspection found the outfit worker alive but not the report thread. The provider later restored its exact owned files and original mod profile after normal game exit. No direct game write or forced process termination was performed by these diagnostics.

Confirmed race: the unchanged native header's session_make_plain_directory checks absence and then creates a directory, but does not accept ERROR_ALREADY_EXISTS if another thread creates it between those steps. The DLL starts both its loader-report and outfit workers concurrently. WPF precreates Logs/game-session before launch; Rust did not. A deterministic two-thread fixture against that original header reproduces exactly one false failure while the folder exists, then verifies both workers pass with a prepared folder and make zero creation calls. This matches the observed first-run failure. Rust now creates and pins the plain directory tree before any DLL publication or Steam dispatch, rejects linked/foreign parents before creating children through them, and retains those directory handles for the session.

The original C++ sources and production DLL remain untouched. The shipped DLL is still 956,416 bytes, SHA-256 ECEF8C6C856A60AF3387BE50D76BD30B53A80F80F404476F5C31D5A5453E91DF. A temporary diagnostic-wrapper experiment was tested privately but is not shipped. No added game-memory writes, hooks, native engine calls or runtime are introduced by this fix. File-only resolver/path and isolated synthetic exact-DLL legacy/portable report checks passed as supporting diagnostics.

Confirmed status defects fixed: a cleanup blocker no longer replaces the original activation failure; rejected loader reports are surfaced instead of being hidden behind the general 90-second arming timeout. Reports remain bounded, PID-specific, current-session-only, and non-reparse. Foreign/unknown report formats fail closed.

Arena foundation: an immutable, flushed ownership receipt precedes synthetic memory writes; apply/restore uncertainty holds ownership until verified game exit. Restart recovery never replays saved memory addresses. All five focused transaction tests passed. This foundation is not connected to public/live controls in this QA. Automatic outfits, arenas, balls, scoreboards, crowd and other Blacktop feature writes remain disabled.
