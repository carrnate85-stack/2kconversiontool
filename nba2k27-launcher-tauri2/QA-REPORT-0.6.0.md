# Rust / Tauri 2 prototype 0.6.0 — session foundation, 2026-10-11

Isolated offline QA milestone. WPF remains Main; no full-parity or live-game acceptance claim.

## Implemented

- On-demand Play → Launch readiness uses native Windows process enumeration. PID, executable path and exact creation FILETIME are read with query-only handles; creation time stays a string across JSON to avoid JavaScript precision loss.
- Primary-library Steam manifests are parsed with bounded quoted-VDF parsing, nesting limits, top-level identity checks, canonical positive app IDs and duplicate-key/duplicate-match refusal. The reported plan retains the exact without-EAC launch option. It is not executed.
- Unknown process/file presence, a running game, anti-cheat process, an unowned existing `version.dll`, or pending/damaged prototype recovery journal blocks eligibility. Unknown is never treated as game-closed. Files are left untouched.
- Strict future journal schema validates phases, exact process identities, role/session ownership, hashes, ownership limits and relative paths. Traversal, ADS, Windows device names, trailing-dot/space aliases and duplicate targets are refused. Invalid journals are preserved.
- Private ownership/restoration policies refuse reused PIDs, foreign executable paths/hashes/sessions, changed user files and damaged backups. Restoration plans inspect observed reparse points and hashes without deleting/overwriting files. Future executors still need fresh checks immediately before each action.
- Pure restoration batching checks game-closed before every step, collects independent failures, and retains prior failure context if a later game-presence check aborts. Cleanup gating is retryable after failure and rejects duplicate completed cleanup.
- Pure rearming policies cover Main Menu, Quick Play, other modes and the next selection screen. Unknown boundaries hold, stale acknowledgements are refused, and failed restoration prevents rearming.

The journal format and ownership/restoration/rearming policies are regression-tested foundations, **not connected production actions**. There is no native launch executor, helper registration/termination, live boundary detector or actual session restoration yet. No live journals are created. Process absence alone does not establish offline/EAC-free status or game-build compatibility.

## Remaining work and limitations

Next: private native action executor, trustworthy packaged-helper whitelist/leases, game-build and without-EAC compatibility gates, durable session transactions, real mode-boundary observations, then a complete Blacktop launch → selection → match → Quick Play → second match → shutdown acceptance test. The policies in this release cannot establish any of that live behavior by themselves.

Secondary Steam-library resolution is not ported; malformed manifests in the selected library conservatively block preflight. Live F8, Blacktop writes, camera tracking, startup-video timing/Xbox/Mixer, in-game Jukebox, live roster/team/staff writes, strategy/playbooks, mannequin/animations, support captures and WPF migration/update transactions remain unported. Existing offline features are retained.

The earlier Rust 1.99.0 compiler/environment fault remains undiagnosed. The optimized build uses one-core affinity on its isolated build shell only, not a persistent system change or reduced optimization. Fresh app acceptance repeats must run unpinned. Passing checks do not prove a reproducible clean-build fix; see earlier QA reports.
