# 0.22.0 native loader publication fix

Isolated QA verification passed on 2026-10-16 at 09:09 Eastern; live launch acceptance is pending. No Main install or Data/Library migration.

Confirmed defect: `FILE_RENAME_INFO.FileName` lacked an explicitly allocated terminating UTF-16 NUL. The old allocation relied on allocator alignment padding. The user's exact 66-character `version.dll` destination allocated 152 bytes with no spare terminator; 0.21's live log identified that publication as failing with 0x80070003 before Steam dispatch. The new in-memory contract regression failed against the old code (`152 bytes, needs 154`) before the fix, then passed. Publication now allocates explicit zero-terminated storage while preserving byte-count semantics, exact-handle ownership and no-replace behavior. It does not weaken checks or fall back to overwriting/copying files.
