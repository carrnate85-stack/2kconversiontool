# 0.27.0 selected mod-folder QA

Isolated release verification passed on 2026-10-16 at 11:50 Eastern. Main WPF, its Data/Library and QA0.26 are not replaced. This is not a full-feature completion claim.

Final results: 301 native tests passed, zero failures, 50.54 seconds sequential. The one separately invoked read-only user-folder audit is deliberately excluded from the ordinary suite. All 31 frontend tests, strict TypeScript and Vite passed. The final EXE passed 97 packaged UI checks plus two fresh-profile, normal-affinity repeats (97 each). Original WPF shared-file validators, browser HTTP/authentication/refused-no-game-save checks and independent provider-worker lifecycle checks passed. Worker shutdown was 81.90 ms; warm fixture UI-ready times were 548 ms and 587 ms, not cold-start guarantees. No automated test launched or accessed live game memory. The launch confirmation screenshot was visually inspected; live selector/count display and gameplay are not claimed verified.

Confirmed gaps fixed: named packages under mods/players/<player> and char/sig/<player> were indexed only at their storage paths, not made available at the normal char/sig resource paths. The launch also left the proven native selector allowlist disabled despite the user's existing three prepared archives. 0.27 connects both paths for the whole selected profile, not a one-player allowlist.

Player packages use shared-data NTFS links, not copies. Loose char/sig files win. Duplicate package filenames fail before any links are published. Every companion IFF directly in each supported package is included; nested sub-packages keep the reference behavior. A create-new receipt precedes staged links; a durable publish boundary precedes no-replace, handle-based renames. Read/write/delete pins and exact volume/file/birth identities bind publication and cleanup. An identical loose link appearing during a failed publication is not treated as owned when the staged link remains. Normal exit/restored sessions remove only exact owned links. Original sources and user replacements stay intact; if a source disappears/replaces the last copy, recovery holds instead of deleting it. Both alternate-profile pre-activation interruption and active-junction recovery are covered. Recovery receipts block another launch and are never adopted without the matching journal/profile root. Canonical empty char/sig directories may remain, as in the reference; mod data is never copied.

The three selector IFF/ZIP files are bounded, path/duplicate/CRC/inflation-checked and validated as a coordinated player-ID set. Handles deny edits/deletion during the snapshot; the entire validated bundle is published atomically as immutable provider bytes. Subsequent disk edits cannot mix archive generations for this game. The unchanged DLL's SELECTOR_OVERRIDE allowlist covers only those three paths; the native activation report must confirm ON/OFF before active status. No general provider-first stock override or native hook change is made. The UI reports verified linked-file and selector-record counts only after loader activation. Automatic stock extraction/new selector generation remains unfinished, though pure clone/list/headband/registry builders now have reference regression coverage.

A production-order cleanup regression was reproduced before delivery: cancelled providers retained cached file handles, so NTFS link deletion could remain pending after the receipt was cleared. Shutdown now drains the transport and every read lease, then explicitly releases cached handles before link/profile restoration. Both the formerly failing cached-player-link case and a transport-level delete-before-server-drop regression pass. The intermediate EFA19444 candidate is superseded, not the release.

Offline evidence so far: 60 synthetic table-generation cases match the original WPF implementation byte-for-byte; eight link/recovery cases, native provider canonical-path serving, ZIP safety and UI status tests pass. A separately invoked, explicitly read-only audit of the actual selected mods folder indexed 414 assets and validated all three existing archives (3,430 player records) in 927 ms. A read-only filename inventory found 361 candidate player files, zero ambiguous names/loose conflicts and all seven Amir Johnson files, including png1452.iff. Neither audit changed mod/game files or accessed game memory. The manual audit is deliberately excluded from the ordinary automated suite.
